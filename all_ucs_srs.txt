UC-01 | Register Account | FE-01 Account & Subscription | Guest registers as Event Organizer or Worker. Worker registers with email and password, receives OTP via email for verification, and account is automatically activated. Event Organizer registers with email, password, phone number, company name, and uploads CCCD images for manual approval by Admin before account activation.
UC-02 | Login | FE-01 Account & Subscription | Registered user logs into the platform using email and password. The system validates credentials, checks account status (Active, Suspended, Banned), and issues a session token upon success. Failed attempts are logged; repeated failures may trigger a temporary lockout per platform security policy.
UC-03 | Logout | FE-01 Account & Subscription | Authenticated user terminates the current session by logging out. The system invalidates the session token, clears local credentials, and redirects the user to the login screen. All unsaved data is discarded upon logout.
UC-04 | Reset Password | FE-01 Account & Subscription | User requests a password reset by providing a registered email address. The system sends a reset link valid for 15 minutes; the link expires after a single use. If the link expires before use, the user must request a new one. Account status must be Active for the reset to proceed.
UC-05 | Change Password | FE-01 Account & Subscription | Authenticated user changes their password by providing the current password and a new password meeting platform complexity requirements. The system validates the current password, updates credentials, and invalidates all active sessions except the current one to enforce re-authentication on other devices.
UC-06 | Verify Email | FE-01 Account & Subscription | After registration, the system sends an OTP or verification link to the user's registered email address. The user enters the OTP or clicks the link to confirm email ownership. Worker accounts are activated immediately upon verification; Event Organizer accounts remain pending Admin approval after email is verified.
UC-07 | View Own Profile | FE-01 Account & Subscription | Authenticated user views their own profile page, including personal information, contact details, account status, role, subscription history, and—for Workers—Skill Point summary, Reliability Score, and verification badges. Event Organizers see company information and active package details.
UC-08 | Edit Own Profile | FE-01 Account & Subscription | Authenticated user updates editable profile fields such as display name, phone number, avatar, and bio. Workers may also update job preferences and working area within this flow. Changes to sensitive fields such as email or legal identity require re-verification. Saved changes take effect immediately.
UC-09 | View Account Status | FE-01 Account & Subscription | Authenticated user views their current account status: Active, Pending Approval, Suspended, or Banned. Workers additionally see their Reliability Score tier (Good / Normal / Warning / Restricted / Locked) and any active restriction reason. Banned accounts display the ban reason and appeal channel.
UC-10 | View Package Plans | FE-01 Account & Subscription | Event Organizer views all available subscription packages including Invite Mode (50,000 VND/Event) and Matching + Invite Mode (80,000 VND/Event), with a breakdown of features, usage quotas, and pricing. The system displays remaining quota from the current active package and highlights recommended plans based on usage history.
UC-11 | Purchase Package via VNPay | FE-01 Account & Subscription | Event Organizer selects a service package and completes payment through VNPay integration. The system records the transaction, credits the purchased quota to the EO's account, and sends a payment confirmation notification. Failed or cancelled payments return the EO to the package selection screen without quota change.
UC-12 | View Subscription History | FE-01 Account & Subscription | Event Organizer views a chronological history of package purchases, including package type, purchase date, amount paid, transaction reference, and remaining quota. The system displays both active and expired subscriptions, allowing EO to track usage and plan future purchases accordingly.
UC-13 | Manage Notifications | FE-01 Account & Subscription | Authenticated user configures notification preferences, including which event types trigger alerts (Shift proposals, Assignment updates, Payment confirmations, Dispute notifications) and the delivery channel (in-app, email). Users can enable or disable individual notification categories while retaining mandatory system alerts.
UC-14 | Search Events | FE-02 Event & Shift Management | Event Organizer searches and filters events by keyword, date range, status (Draft, Active, Completed, Archived), location, and staffing status such as Fully Staffed or Understaffed. Search results display event cards with key information and quick status indicators for rapid assessment.
UC-15 | Create Event | FE-02 Event & Shift Management | Event Organizer creates a new event by providing name, description, start and end date, venue location, and selecting a recruitment mode (Invite Mode or Matching + Invite Mode). The system validates package quota availability and deducts one usage credit upon confirmation before setting the event status to Draft.
UC-16 | View Event Details | FE-02 Event & Shift Management | Event Organizer views full details of an event including event metadata, list of Shifts with individual staffing progress, Assignment summary, and overall readiness status. The system also displays total confirmed Workers versus required headcount across all Shifts to support EO decision-making.
UC-17 | Edit Event | FE-02 Event & Shift Management | Event Organizer edits event metadata such as name, description, venue, or dates while the event is in Draft or Active status. Edits to Active events that affect already-confirmed Assignments trigger notifications to affected Workers. Changes are logged with a timestamp for audit purposes.
UC-18 | Cancel Event | FE-02 Event & Shift Management | Event Organizer cancels an Active or Draft event. The system updates all associated Shifts and Assignments to CANCELLED_BY_EO, notifies affected Workers, and releases their schedule. EO's cancellation history is updated for reputation tracking. Consumed package quota is not refunded upon cancellation.
UC-19 | Activate Event | FE-02 Event & Shift Management | Event Organizer transitions an event from Draft to Active status, making it eligible for Worker invitation or Matching. The system verifies that at least one Shift is configured and the required package quota has been consumed. Activated events appear in relevant Worker feeds based on recruitment mode.
UC-20 | Archive Event | FE-02 Event & Shift Management | Event Organizer archives a Completed or Cancelled event to move it out of the active event list. Archived events remain accessible for historical reference, reporting, and dispute resolution. Data including Assignments, Attendance, and Payment records is preserved in full after archiving.
UC-21 | View Event History | FE-02 Event & Shift Management | Event Organizer views a historical log of all past events including Completed, Cancelled, and Archived status. Each entry shows event name, date, total Shifts, Worker count, overall completion rate, and payment summary. The history supports filtering by date range and event status for reporting purposes.
UC-22 | Create Shift | FE-02 Event & Shift Management | Event Organizer creates a Shift within an event by specifying role, start and end time, venue location, required Worker headcount, mandatory skills and experience, and expected wage. The system automatically retrieves a Wage Matrix recommendation based on City, Job Type, Time Slot, and Lead Time dimensions.
UC-23 | Create Bulk Shifts | FE-02 Event & Shift Management | Event Organizer creates multiple Shifts simultaneously by providing a shared template (role, skills, wage) and specifying multiple time slots. The system validates each Shift entry individually and reports conflicts or validation errors per row, allowing partial batch creation when some entries are valid.
UC-24 | Edit Shift | FE-02 Event & Shift Management | Event Organizer edits Shift details such as headcount, timing, role requirements, or wage while the Shift has not yet reached Fully Staffed status. If confirmed Assignments exist, Workers are notified of material changes and given an option to accept or reject the revised terms before the update is finalized.
UC-25 | Cancel Shift | FE-02 Event & Shift Management | Event Organizer cancels a specific Shift, causing the system to update all linked Assignments to CANCELLED_BY_EO, notify affected Workers, and release their schedule availability. The cancellation event is recorded in the EO's reputation history and may affect EO reliability metrics used by Workers when evaluating future invitations.
UC-26 | View Staffing Progress | FE-02 Event & Shift Management | Event Organizer views the staffing dashboard for an event or individual Shift, showing Required Workers, Confirmed Workers, and Remaining Workers. Shifts that have reached Fully Staffed status are highlighted. The system aggregates headcount across all Shifts to provide an overall Event Readiness indicator.
UC-27 | Post Shift for Matching | FE-02 Event & Shift Management | Event Organizer activates the Matching & Dispatch process for a Shift in Matching + Invite Mode. The system validates eligibility, then runs the Matching Engine to produce a ranked candidate list. EO reviews the list and selects Workers to invite; the system does not automatically dispatch to the full candidate list.
UC-28 | View Wage Recommendation | FE-03 Wage Matrix Management | When creating or editing a Shift, Event Organizer views the recommended wage retrieved from the 4-dimensional Wage Matrix (City × Job Type × Time Slot × Lead Time). The system displays the recommended rate alongside the EO's entered wage, with a comparison indicator: below market, at market, or above market level.
UC-29 | Set Shift Wage | FE-03 Wage Matrix Management | Event Organizer sets the final wage for a Shift after reviewing the Wage Matrix recommendation. If the entered wage is significantly below the reference, the system displays a warning about potential low fill-rate risk. If significantly above, it notes the above-market premium. Final wage decision belongs to the EO.
UC-30 | View Wage Matrix | FE-03 Wage Matrix Management | Admin views the current Wage Matrix table organized by City, Job Type, Time Slot, and Lead Time dimensions, with a total of up to 405 combinations. The display includes the configured wage per hour for each row, last modified timestamp, and fallback-usage statistics to identify missing combinations.
UC-31 | Configure Wage Matrix | FE-03 Wage Matrix Management | Admin adds, edits, or deletes rows in the Wage Matrix using a CRUD interface, with Import/Export CSV support for bulk updates. The system provides a test lookup tool where Admin inputs Shift parameters to preview the returned recommendation and fallback level (0–3). Changes are versioned with a change log for audit purposes.
UC-32 | Manage Skills | FE-04 Worker Profile & Preferences | Worker adds, edits, or removes skills with proficiency levels: Beginner, Intermediate, Advanced, or Expert. Declared skills are tagged as Self-Declared until verified. Skills affect Eligibility Filtering and the Skill Match component of the Matching Score. Shifts requiring verified skills only accept Workers with the corresponding verification status.
UC-33 | Manage Experience | FE-04 Worker Profile & Preferences | Worker declares, edits, or removes relevant work experience by specifying role, job category, duration, and a brief description. Experience data contributes to the Relevant Experience component (15% weight) in the Matching Score. Self-declared experience is distinguished from Platform-Proven records automatically generated from completed Assignments.
UC-34 | Upload Portfolio | FE-04 Worker Profile & Preferences | Worker uploads portfolio items such as event photos, videos, or project samples to support skill verification. Uploaded files are associated with specific skill or role claims and are reviewed by Admin as part of the AI Document Verification process (Iter 3). Portfolio items are visible to Event Organizers on the Worker's public profile.
UC-35 | Declare Availability | FE-04 Worker Profile & Preferences | Worker declares recurring weekly availability by selecting available days and time slots, and can override specific dates for exceptions. The declared availability is used by the Matching Engine during Eligibility Filtering to identify schedule conflicts with candidate Shifts. Availability is editable at any time but does not retroactively affect confirmed Assignments.
UC-36 | Set Working Area | FE-04 Worker Profile & Preferences | Worker sets preferred working areas by selecting province/city and district(s). The system optionally uses the Worker's current GPS location as a suggestion but does not enforce GPS as a mandatory input. Working area contributes to the Location Match component (15% weight) of the Matching Score during candidate ranking.
UC-37 | Declare Job Preferences | FE-04 Worker Profile & Preferences | Worker declares preferred job roles (e.g., Guest Support, Waiter, MC, Security) and optionally sets a minimum expected wage. Declared preferences are used to personalize the Job Feed and improve Matching relevance. If the minimum wage is set as a hard filter, the system excludes Shifts below this threshold during Eligibility Filtering.
UC-38 | Block EO | FE-04 Worker Profile & Preferences | Worker adds a specific Event Organizer to their personal block list, preventing that EO from sending Shift proposals or invitations to the Worker. The block action is silent to the EO and does not affect existing confirmed Assignments. Blocked EOs are excluded from the Dispatch pipeline for all future Shifts posted by that EO.
UC-39 | Manage Blocked List | FE-04 Worker Profile & Preferences | Worker views, reviews, and manages their list of blocked Event Organizers. The list displays EO name, block date, and optional reason note. Workers can unblock an EO at any time, immediately restoring proposal eligibility. The blocked list is private and visible only to the Worker.
UC-40 | View Public Profile | FE-04 Worker Profile & Preferences | Event Organizer or Admin views a Worker's public profile, which includes display name, declared skills with verification badges, experience summary, Skill Point Tier (Starter to Master), Reliability Score, average Rating, completion statistics, and recent EO reviews. Sensitive personal data is hidden per platform privacy policy.
UC-41 | View Skill Point | FE-05 Skill Point & Verification | Worker views their accumulated Skill Points (SP) per role, broken down by source: SP_verify (from verified credentials), SP_experience (from completed Assignments), and SP_rating (from EO evaluations). The current Tier (Starter, Bronze, Silver, Gold, Platinum, Diamond, Master) and the SP threshold for the next Tier are clearly displayed.
UC-42 | Submit Self-Declared Verification | FE-05 Skill Point & Verification | Worker completes Tier 1 verification (Self-Declared) by selecting skills from the platform's standardized Skill Taxonomy during profile setup. No documents are required. This grants Starter-tier status with zero SP_verify and enables the Worker to pass Eligibility Filtering for standard Shifts that do not require verified credentials.
UC-43 | Submit AI Document Verification | FE-05 Skill Point & Verification | Worker uploads credential documents (CV, degree certificate, professional certificate, or portfolio image in PDF, DOCX, JPG, or PNG format) for Tier 2 AI-powered verification (Iter 3 — post-MVP). The system extracts skills, maps them to the Skill Taxonomy, and returns a confidence score. Auto-approved if confidence ≥ 0.85; routed to Admin review queue if 0.60–0.84; rejected if below 0.60.
UC-44 | Request Platform Verification | FE-05 Skill Point & Verification | Worker applies for Tier 3 (Platform-Proven) verification status for a specific role. The system automatically grants this status when the Worker has completed at least 3 Assignments for that role on CANi with an average Rating ≥ 4.5/5.0 and no active Disputes. No manual application is required; the system evaluates eligibility continuously.
UC-45 | View Verification Status | FE-05 Skill Point & Verification | Worker views the current verification status for each skill and role, showing Tier level (Self-Declared, AI-Verified, or Platform-Proven), verification date, and awarded SP_verify. For documents pending Admin review, the expected review window (4–12 business hours) is displayed. Rejection reasons are provided for resubmission guidance.
UC-46 | AI Verify Documents | FE-05 Skill Point & Verification | System (AI pipeline, Iter 3) processes uploaded Worker documents through a 5-step pipeline: file ingestion, multimodal extraction (text parser for PDFs, Vision LLM for images), Skill Taxonomy normalization, confidence-based approval routing, and Worker confirmation of recognized skills. Output includes Skill ID, evidence snippet, and confidence score per skill.
UC-47 | Admin Review Verification | FE-05 Skill Point & Verification | Admin reviews Worker credential documents queued for manual verification (confidence score 0.60–0.84 from AI pipeline). Admin compares AI-extracted skill claims against the uploaded evidence, approves or rejects each claim, and sets awarded SP_verify accordingly. Review decisions are logged and the Worker receives a notification with outcome and reason.
UC-48 | Calculate & Assign Tier | FE-05 Skill Point & Verification | System recalculates a Worker's total Skill Point per role after each SP-affecting event (completed Assignment, EO rating, or successful verification) and assigns the corresponding Tier: Starter (0–49), Bronze (50–149), Silver (150–299), Gold (300–599), Platinum (600–999), Diamond (1000–1499), or Master (1500+). Tier change triggers a notification to the Worker.
UC-49 | View Shift Proposals | FE-06 Matching Engine | Worker views incoming Shift proposals from two sources depending on Online Status: in Job Feed (online mode — proposals appear in real-time when the app is open) or via email notification (offline mode — proposals are delivered by email when the Worker is not active on the platform). Each proposal card displays role, date, location, duration, and offered wage.
UC-50 | Filter Proposals | FE-06 Matching Engine | Worker applies filters to the Shift proposal list, including role type, date range, location/district, wage range, and event type. The system re-ranks the filtered results while preserving Matching Score order. Filters are session-based and do not permanently alter the Worker's declared preferences or Matching parameters.
UC-51 | View Proposal Details | FE-06 Matching Engine | Worker views the full details of a Shift proposal, including event name, role description, shift timing, venue address, required skills, checklist preview, offered wage compared to market reference, and Event Organizer's average rating. The Match Score Breakdown is optionally shown to explain why the proposal was generated.
UC-52 | Accept Shift | FE-06 Matching Engine | Worker accepts a Shift proposal within the response deadline. The system performs a real-time re-check of account status, schedule conflicts, and remaining slot availability before creating an Assignment. If any condition fails at acceptance time, the system declines the creation and notifies the Worker. Accepted Shift updates the staffing counter for that Shift.
UC-53 | Reject Shift | FE-06 Matching Engine | Worker declines a Shift proposal by selecting a rejection reason. The system updates the proposal status to REJECTED, removes it from the Worker's proposal list, and notifies the Event Organizer. The EO may then select additional Workers from the candidate list. Rejection does not affect the Worker's Reliability Score.
UC-54 | Toggle Online Status | FE-06 Matching Engine | Worker toggles their availability mode between Online and Offline. In Online mode, Shift proposals are delivered via Job Feed when the app is active. In Offline mode, proposals are routed via email instead of real-time in-app notifications. Real-time push notification dispatch is replaced by this dual-mode routing mechanism. The toggle is accessible from the app's main navigation bar.
UC-55 | Configure Matching Preferences | FE-06 Matching Engine | Worker configures Matching Engine input parameters including maximum travel distance, preferred job roles, minimum wage threshold, and days/times of availability. These preferences are used as weighted inputs in the Matching Score calculation and as filters during Eligibility Filtering. Changes take effect on the next Dispatch cycle.
UC-56 | View Match Score Breakdown | FE-06 Matching Engine | Worker or Event Organizer views a breakdown of the Matching Score for a specific Worker-Shift pairing, showing individual component scores and weights: Skill Match (40%), Relevant Experience (15%), Location Match (15%), Reliability (20%), and Rating (10%), plus any applied Fairness Boost adjustments (New Worker Boost or Idle Worker Boost).
UC-57 | Calculate Match Score | FE-06 Matching Engine | System calculates each eligible Worker's Matching Score using the Weighted Sum Model: 40% Skill Match (from Skill Point Tier), 15% Relevant Experience, 15% Location Match, 20% Reliability, and 10% Rating. Fairness Boost adds up to +15 points for new Workers (< 3 completed Assignments) or +20 points for idle Workers (no Assignments in 7 days). Result is used to rank the candidate list.
UC-58 | Monitor Readiness | FE-06 Matching Engine | Event Organizer monitors the real-time readiness status of all Shifts within an event, including Fully Staffed, Partially Staffed, and Understaffed indicators. The system highlights Shifts at risk of insufficient staffing before the event date, enabling proactive dispatch of additional invitations or use of Emergency Dispatch.
UC-59 | Trigger Emergency Dispatch | FE-06 Matching Engine | System automatically triggers Emergency Dispatch when a confirmed Assignment is cancelled or a No-show is recorded and the Shift falls below required headcount. The system re-runs Matching and extends invitations to next-ranked eligible Workers. Event Organizer is notified and can also manually trigger Emergency Dispatch for critical understaffed Shifts.
UC-60 | Apply Fairness Boost | FE-06 Matching Engine | System applies Fairness Boost adjustments to the Matching Score after the base score is calculated. New Worker Boost (+10 to +15 points) applies to accounts created within 14 days or with fewer than 3 completed Assignments. Idle Worker Boost (+20 points) applies to Workers with no Assignments in the past 7 days. Top-tier Workers are capped at 40% of dispatch slots per region per cycle.
UC-61 | Configure Fairness Rules | FE-06 Matching Engine | Admin configures the Fairness & Opportunity Guardrails parameters, including New Worker Boost range, Idle Worker Boost value, the inactivity threshold (default 7 days), Star Worker dispatch cap percentage (default 40%), and the Slot Reservation ratio for Starter/Bronze Workers in candidate lists (default 20–30%). Changes are logged and applied to the next Matching cycle.

UC-63 | View Assignment Details | FE-07 Assignment & My Team | Worker or Event Organizer views the full detail page of a specific Assignment, including role description, Shift schedule, venue address, EO/Worker contact summary, Checklist items, Attendance records (Check-in/Check-out timestamps), and Payment Status. UC-90 | Rate Worker | FE-10 Rating & Reputation | Event Organizer rates a Worker within 7 days of Shift completion across five weighted criteria: task completion (30%), punctuality (25%), professional attitude (20%), venue compliance (15%), and teamwork (10%). The weighted average determines the star rating (1–5). Ratings contribute to the Worker's SP_rating and Reliability Score. The window closes automatically after 7 days, defaulting to 5 stars.
UC-91 | Rate EO | FE-10 Rating & Reputation | Worker rates an Event Organizer within 7 days of Shift completion across five weighted criteria: Shift description clarity (30%), schedule accuracy (20%), working environment quality (20%), on-site support (15%), and payment timeliness (15%). EO ratings form part of the EO reputation profile visible to Workers when evaluating future proposals.
UC-92 | View Ratings | FE-10 Rating & Reputation | User views the rating history for a Worker or Event Organizer, including individual star scores, per-criterion breakdowns, reviewer display name, Shift date, and review text. Workers view ratings on their profile; EOs view Worker ratings when considering candidates. Admin can view all ratings for moderation and anti-abuse enforcement purposes.
UC-93 | View Reliability Score | FE-10 Rating & Reputation | Worker views their current Reliability Score (RS, scale 0–100), including the tier classification: Good (80–100), Normal (60–79), Warning (40–59), Restricted (20–39), or Locked (< 20). The view displays the score breakdown by contribution type: completed shifts, cancellations, no-shows, and EO ratings, along with any active restrictions on account features.
UC-94 | RS Penalty & Appeal | FE-10 Rating & Reputation | When an RS penalty is applied (e.g., −25 for no-show, −20 for late cancel, −10 for T-24h cancel), the Worker is notified with the reason and updated score. Worker may submit an Appeal within 7 days by providing supporting evidence for force-majeure cases. Admin reviews the appeal and may restore RS points; the decision is final and logged for audit.
UC-95 | Lock/Unlock Account | FE-10 Rating & Reputation | System automatically locks a Worker account when the Reliability Score drops below 20. A locked account cannot receive new Shift proposals or check in to active Assignments. Admin may manually unlock the account after reviewing the Worker's history and appeal submission. Locked status and unlock reasons are recorded in the account audit log.
UC-96 | Submit Dispute | FE-11 Dispute & Resolution | Worker or Event Organizer submits a Dispute against the other party regarding work completion quality, payment discrepancy, No-show, or conduct violation. The submitting party provides a dispute category, description, and initial evidence. The Assignment is set to DISPUTED status, pausing any pending payment confirmation, and the case enters the Customer Care queue.
UC-97 | View Dispute Details | FE-11 Dispute & Resolution | Involved parties (Worker, EO, Customer Care, Admin) view the full Dispute record, including the original complaint, submitted evidence from both sides, QR Attendance logs, Checklist completion records, and any communications logged on the platform. The current resolution status and assigned CC agent are also displayed.
UC-98 | Upload Evidence | FE-11 Dispute & Resolution | Worker or Event Organizer uploads supporting evidence for an active Dispute, including images, videos, document scans, or transaction records. Uploaded evidence is timestamped and linked to the specific Dispute case. Both parties may upload evidence within the defined submission window. Evidence labels distinguish party-submitted documents from system-generated logs.
UC-99 | CC Receives & Investigates | FE-11 Dispute & Resolution | Customer Care agent accepts a Dispute from the queue and begins investigation by reviewing QR Attendance timestamps, system logs, Checklist data, and evidence submitted by both parties. CC may request additional information from either party within a defined response window. Investigation findings are recorded in the Dispute record before a decision is issued.
UC-100 | CC Issues Decision | FE-11 Dispute & Resolution | Customer Care agent issues a resolution decision based on collected evidence, selecting an outcome: resolved in favor of EO, resolved in favor of Worker, partial resolution, or marked as Unverified due to insufficient evidence. The decision is communicated to both parties with reasoning. Either party may escalate to Admin within 7 days if they disagree with the outcome.
UC-101 | Escalate to Admin | FE-11 Dispute & Resolution | Worker or Event Organizer escalates a CC-issued Dispute decision to Admin level within 7 days of receiving the outcome. The escalation request must include the reason for disagreement and any new evidence not previously submitted. Admin is notified of the escalation and the case is transferred to the Admin review queue with full Dispute history.
UC-102 | Admin Reviews & Decision | FE-11 Dispute & Resolution | Admin reviews an escalated Dispute, examining all evidence, CC investigation notes, and new information provided during escalation. Admin issues a final binding decision that overrides the CC ruling, selecting from: uphold CC decision, reverse in favor of either party, or maintain UNVERIFIED status. The final decision is logged and communicated to all parties.
UC-103 | Apply RS Penalty | FE-11 Dispute & Resolution | System or Admin applies Reliability Score penalties to the party found at fault in a resolved Dispute, according to the platform's published penalty schedule. Penalties may include RS point deductions, temporary feature restrictions, or account suspension depending on severity and recurrence. The penalty is logged in the account's audit history.
UC-104 | View Dispute History | FE-11 Dispute & Resolution | Worker, Event Organizer, or Admin views the historical log of all Disputes involving their account, including Dispute category, submitted date, resolution status, outcome, and any applied penalties. Admin can search and filter all platform Disputes by actor, date range, category, and resolution outcome for reporting and quality monitoring.
UC-105 | Submit Support Ticket | FE-12 Customer Care | Worker or Event Organizer submits a support request for issues not covered by the Dispute process, such as account access problems, billing queries, or platform usage questions. The submitter selects a category, provides a description, and optionally attaches screenshots. The system auto-assigns the ticket to a CC agent based on category and generates a tracking reference number.
UC-106 | Track Support Ticket | FE-12 Customer Care | User views the status and communication thread of a submitted support ticket, including current status (Open, In Progress, Resolved, Closed), assigned CC agent name, latest response, and expected resolution time. Users can add follow-up replies or attach additional information to an open ticket directly from the tracking view.
UC-107 | Manage Member Accounts | FE-12 Customer Care | Customer Care agent reviews, approves, or rejects Event Organizer account registration applications by verifying submitted CCCD documents and company information. CC can flag accounts for additional review, request resubmission of documents, or escalate to Admin for borderline cases. All actions are recorded with timestamps and agent identifier.
UC-108 | View Revenue Dashboard | FE-12 Customer Care | Admin or Finance role views the platform revenue dashboard showing total package sales, revenue by package type (Invite Mode vs. Matching + Invite Mode), transaction count, and period-over-period comparison. The dashboard includes VNPay transaction status summary and flags any failed or refunded transactions for follow-up.
UC-109 | Manage Dispute Queue | FE-12 Customer Care | Customer Care agent views and manages the queue of open Disputes, filtering by category (payment, work quality, conduct), priority, age, and assigned agent. CC can self-assign cases, transfer cases to colleagues, set response deadlines, and escalate overdue cases. Queue metrics including average resolution time are displayed for performance monitoring.
UC-110 | Manage FAQ | FE-12 Customer Care | Admin or Customer Care agent creates, edits, archives, or publishes FAQ articles organized by category (Account, Shift, Payment, Dispute). Published FAQs are surfaced in the platform's help center accessible to all users. Analytics on FAQ view counts and ticket deflection rates are available to identify gaps in self-service content.
UC-111 | View System Dashboard | FE-13 System Administration | Admin views the operational system dashboard displaying key platform metrics: active Events, total Assignments by status, Dispute queue size, Reliability Score distribution across Workers, Matching Engine performance indicators, and platform revenue summary. Real-time alerts for anomalies such as high no-show rates or RS threshold breaches are displayed prominently.
UC-112 | Manage Users (CRUD) | FE-13 System Administration | Admin creates, reads, updates, or deactivates user accounts for all roles (Worker, Event Organizer, Customer Care, Admin). Admin can force-reset passwords, change account status, update role assignments, and view full account history including login events, Dispute records, and RS history. All modifications are logged in the system audit trail.
UC-113 | Manage Roles (RBAC) | FE-13 System Administration | Admin configures Role-Based Access Control by defining permissions for each system role (Worker, Event Organizer, Customer Care, Admin, Finance). Admin can create custom roles, assign feature-level permissions, and review the access matrix. Changes to roles immediately apply to all accounts holding that role. RBAC changes are logged and auditable.
UC-115 | Configure Skill Point Rules | FE-13 System Administration | Admin configures Skill Point accrual rules including SP awarded per Assignment type (short shift +5, standard +10, long shift +15), SP from EO rating (5-star +5, 4-star +3, below 3.5 −3), SP from late cancel (−8) and no-show (−15), and Role Alignment Factor multipliers for related and unrelated skill matches (100%, 50%, 20%).
UC-116 | System Maintenance & Configuration | FE-13 System Administration | Admin manages system-level maintenance tasks including database backup scheduling, cache invalidation, feature flag toggling for staged rollouts, and service health monitoring. Admin can enable or disable specific platform features (e.g., AI Verification, Matching Engine) without a code deployment, using the platform's configuration management interface.
UC-114 | Configure System Parameters | FE-13 System Administration | Admin configures global platform parameters including Invite Mode pricing (default 50,000 VND/Event), Matching + Invite Mode pricing (default 80,000 VND/Event), No-show detection threshold (default 30 minutes), rating window duration (default 7 days), and RS thresholds for each tier. Parameter changes are versioned and do not affect active transactions.
UC-117 | Send Notifications | SUP Common Services | System sends platform notifications to users via configured delivery channels (in-app and email) based on trigger events such as Shift proposal received, Assignment status change, Payment declaration, Dispute update, and RS change. Notification content is templated per event type and respects each user's notification preference settings configured in UC-13.
UC-118 | Dispatch Proposals (Online/Offline) | SUP Common Services | System dispatches Shift proposals to eligible Workers using a dual-mode routing mechanism: in Online mode, proposals are delivered via Job Feed when the Worker's app is active; in Offline mode, proposals are sent via email. The dispatch route is determined by each Worker's current Online Status toggle (UC-54). Real-time push notifications are not used; routing is mode-based per Worker preference.
UC-119 | Upload & Validate Files | SUP Common Services | System provides a shared file upload service used across platform features (profile photo, portfolio, verification documents, payment evidence, Dispute attachments). The service validates file type (PDF, DOCX, JPG, PNG), file size limits, and virus scan before storing. Failed validations return descriptive error messages to the uploading user with guidance for resubmission.
UC-120 | Search | SUP Common Services | Platform provides a unified search service enabling keyword-based and filter-based lookup across entities: Events (by name, date, status), Workers (by name, skill, Tier), Disputes (by ID, actor, status), and Support Tickets (by reference, category). Search results are role-scoped so users only see records they are permitted to access per RBAC configuration.
UC-121 | Audit Log | SUP Common Services | System records an immutable audit log entry for every significant action on the platform, capturing actor identity, action type, affected entity, timestamp, IP address, and before/after state for data changes. Admin can query the audit log by actor, entity, date range, and action type. Audit records are retained per the platform's data governance policy and support compliance reporting.
