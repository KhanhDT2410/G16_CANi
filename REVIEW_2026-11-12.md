## 1. P0 — Sửa trước khi demo (chặn chất lượng)

### 1.1 [Mobile] Ca làm hiển thị lệch 7 tiếng (UTC+7)
- **File:** `mobile/lib/features/job_proposals/models/proposal_models.dart:45-46,116-117`
- **Vấn đề:** Backend trả `java.time.Instant` (ISO-8601 kèm `Z`). `DateTime.tryParse` cho ra DateTime **UTC**, nhưng UI render thẳng `a.startTime.hour` (`shift_assignment_card.dart:181`, `job_detail_bottom_sheet.dart:198`, `job_proposal_dispatch_card.dart:129`, `urgent_shift_hero_card.dart:169`).
- **Hệ quả:** Trên máy VN, mọi giờ ca hiển thị sớm 7 tiếng. Countdown ở `shift_detail_execution_screen.dart:78-81` so `target.difference(DateTime.now())` với target chưa localize → worker thấy "đã kết thúc 7 tiếng trước" hoặc "còn 7 tiếng nữa mới bắt đầu".
- **Fix (1 chỗ, đúng nguyên tắc DRY):** trong `fromJson` của model: `final dt = DateTime.tryParse(...); return dt == null ? null : (dt.isUtc ? dt.toLocal() : dt);` — mọi consumer được sửa theo.

### 1.2 [Mobile] Cả 2 test đều FAIL → "test pass" là hiện tượng giả
- **File:** `mobile/test/widget_test.dart:39`, `mobile/test/features/profile/profile_screen_test.dart:47`
- **Vấn đề:** `widget_test.dart` đợi text `Đăng Nhập` nhưng sau 5 pump màn hình vẫn ở spinner (auth check chưa stub đủ sâu) → 0 match. `profile_screen_test.dart` đòi text `Sáp ra mắt` trong khi UI thật là `'$profileUrl (Sắp ra mắt)'` → `find.text` (so bằng) fail, cần `find.textContaining`.
- **Hệ quả:** Test là hàng rào an toàn duy nhất của mobile, nhưng đang hỏng → mọi regression sau này đều lọt.
- **Fix:** dùng `find.textContaining(...)`; pump thêm hoặc stub sâu hơn provider auth.

### 1.3 [Web] Crash React do vi phạm Rules-of-Hooks
- **File:** `web/src/features/support-tickets/components/SupportChatWidget.jsx:41` (`if (isStaff) return null;` **trước** `useEffect` ở dòng 43)
- **Hệ quả:** `npm run lint` báo 1 error. Khi user là ADMIN/CUSTOMER_CARE và `isStaff` đổi giữa các render (state từ `useAuth` resolve bất đồng bộ), React ném *"Rendered more hooks than during the previous render"* → ErrorBoundary nuốt **toàn bộ app**, người dùng thấy màn hình reload.
- **Fix:** đưa `useEffect` lên trên `early return`, hoặc tách phần non-staff ra component con.

### 1.4 [Mobile] Build release không boot được nếu thiếu `--dart-define`
- **File:** `mobile/lib/core/constants/api_constants.dart:10-20,26-40`
- **Vấn đề:** `baseUrl` mặc định `http://localhost:8080` (trên máy thật → không resolve host). Tệ hơn: trong release, Supabase/Google key fallback là **chuỗi rỗng** → `Supabase.initialize(url:'', key:'')` tại `main.dart:12-15` ném lỗi ngay lúc khởi động. Không có cấu hình theo flavor.
- **Fix:** bắt buộc `API_BASE_URL` trong release (throw với message rõ ràng nếu thiếu), tách config debug/release, và **ghi lệnh build kèm define vào `run.md`/README**.

## 2. P1 — Bảo mật & kiến trúc auth

### 2.1 [Web] Không có nguồn sự thật duy nhất cho phiên đăng nhập
- **File:** `web/src/features/auth/hooks/useAuth.js` được gọi độc lập ở **7 nơi**: `MainLayout.jsx:14`, `EOPage.jsx:29`, `EoProfileTab.jsx:30`, `DisputeCenterView.jsx:19`, `SupportTicketsCenterView.jsx:18`, `SupportChatWidget.jsx:26`, cộng `RequireRole`/`useAuthGuard`.
- **Hệ quả:** Mỗi nơi tự `isLoading=true` + tự gọi `/auth/me`; StrictMode còn double-fire. N chuyển hướng → N request; `user` có thể `null` ở component này nhưng đã có ở component kia → **route guard và header hiển thị trạng thái đăng nhập khác nhau**. Logout ở `MainLayout` không xóa được các sibling.
- **Fix:** **một `AuthContext` provider ở gốc `App.jsx`**, mọi consumer đọc cùng một nguồn. Đây là thay đổi có ROI cao nhất trong toàn bộ web.

### 2.2 [Web] Refresh token được lưu nhưng không bao giờ dùng → hết phiên là logout
- **File:** `cani_refresh_token` ghi ở `useLogin.js:62`, `AuthCallbackPage.jsx:43`, xóa ở `authApi.js:103` — nhưng **không có đường nào gửi nó tới endpoint refresh**.
- **Hệ quả:** Interceptor 401 (`web/src/services/api.js:29-38`) chỉ xóa localStorage và redirect `/login`. Token hết hạn giữa phiên → mất phiên làm việc.
- **Fix:** retry-once bằng refresh token trong interceptor 401, **hoặc xóa hẳn nhánh refresh-token** nếu không làm. Hiện trạng = code chết gây hiểu nhầm.

### 2.3 [Web] XSS qua rich-text FAQ
- **File:** `web/src/features/faqs/components/FaqCard.jsx:98`, `FaqPublicList.jsx:116` render `faq.answer` bằng `dangerouslySetInnerHTML`. Trình soạn thảo `FaqRichTextEditor.jsx:22-48` dùng `document.execCommand` + `contentEditable` → HTML dán từ ngoài có thể mang `<script>`/`on*` handler. **Không có DOMPurify trong dependencies.**
- **Hệ quả:** Nội dung do Admin/CC nhập (hoặc dán) đẩy vào Help Center công khai → XSS chạy trong session của người dùng cuối.
- **Fix:** sanitize bằng DOMPurify tại **cả hai** điểm render (và tốt hơn là sanitize cả lúc lưu).

### 2.4 [Backend] Latent Local File Inclusion ở 3 endpoint phục vụ ảnh
- **File:** `WorkerJobService.loadProofImage` (~1063), `EoEventService.loadEventImage` (~828), `FaqService.loadFaqImage` (~361) — đều `Paths.get(DIR).resolve(filename).normalize()` rồi trả `UrlResource`, **không kiểm tra containment**.
- **Hiện trạng:** Đã probe thực tế — Tomcat chặn `..%2f` (400) nên **chưa khai thác được** trên container hiện tại. Nhưng tầng ứng dụng không có guard nào; đổi servlet container / deploy config / matrix-param là thành **đọc file tùy ý** — cùng thư mục còn có `.env.bak`, `firebase-service-account.json`.
- **Fix:** thêm guard `file.toPath().startsWith(DIR)` trước khi trả resource ở cả 3 loader. Rẻ, và là defense-in-depth đúng.

### 2.5 [Mobile] Thiếu chống chụp màn hình trên luồng eKYC
- **File:** `mobile/lib/features/ekyc/screens/ekyc_verification_screen.dart`, `cccd_confirm_dialog.dart`
- **Vấn đề:** Hiển thị số CCCD, ảnh selfie, dữ liệu OCR (ngày sinh, địa chỉ) mà không có `FLAG_SECURE` tương đương, không blur nền khi app bị đưa xuống background. Ngoài ra `worker_bank_settings_screen.dart:54-56` đổ **số tài khoản đầy đủ** vào controller (chỉ mask khi hiển thị) → rò qua bàn phím/autocomplete hoặc log `controller.text`.
- **Fix:** bật `FLAG_SECURE` (qua platform channel) cho 3 màn eKYC; mask số tài khoản ngay khi load.

## 3. P2 — Contract nghiệp vụ & độ tin cậy

### 3.1 [Backend] `requiredSkills` được set nhưng không bao giờ được đọc
- **File:** `Shift.java:89` (`requiredSkills`), set tại `EoEventService.java:201`, **không nơi nào đọc trong tầng matching**.
- **Hệ quả:** `MatchingDispatchService.passHardFilter` đã tôn trọng `maxDistanceKm`, `minReliabilityScore`, `minExperienceLevel` — nhưng bỏ sót kỹ năng yêu cầu → **dispatch worker không đủ kỹ năng cho ca**. Đây là mục duy nhất trong báo cáo cũ còn mở.
- **Fix:** thêm kiểm tra overlap kỹ năng trong `passHardFilter` — 1 đoạn.

### 3.2 [Backend] PayOS: đơn pending mất khi restart, `orderCode` có thể trùng
- **File:** `SubscriptionService.pendingOrders` là `ConcurrentHashMap` (dòng 53); `orderCode = abs(nowMillis % 900000000) + 100000000` (dòng 233).
- **Hệ quả:** (a) restart app là webhook của đơn đã trả tiền không còn đơn trong map → **không kích hoạt được subscription**; (b) hai EO tạo session cùng mili-giây → trùng `orderCode`.
- **Fix:** lưu đơn pending vào DB (bảng `payment_orders`) hoặc kích hoạt idempotent từ DB; namespace `orderCode` theo EO.

### 3.3 [Backend] SLA-scan: check-then-act không nguyên tử
- **File:** `SlaMonitoringService` — `existsBy...` rồi `save(new SlaAlertLog)`.
- **Hệ quả:** 2 lần quét đồng thời → cả hai pass check; lần thứ hai đụng unique constraint `uq_sla_alert_log` **throw trong `@Transactional` → abort cả lượt quét**, mọi ticket/dispute còn lại trong batch mất alert + audit log.
- **Fix:** bọc insert trong try/catch `DataIntegrityViolation` (coi như đã cảnh báo), hoặc `INSERT ... WHERE NOT EXISTS`.

### 3.4 [Backend] `deleteEvent` không cascade huỷ shift/assignment
- **File:** `EoEventService.deleteEvent` (~425) — soft-delete Event nhưng **không** huỷ shift/assignment, khác `cancelEvent` (cascades).
- **Hệ quả:** Event đã xoá vẫn để lại shift ACTIVE và worker CONFIRMED. Fix: cho delete cascade-huỷ như cancel, hoặc chặn delete khi còn assignment active.

### 3.5 [Web] `dangerouslySetInnerHTML` + API client nuốt lỗi
- `eoService.js` `getEventDetail`: `catch { console.warn(...); return null; }` → 401/404/500 bị đối xử như nhau. Caller ở `EOPage.jsx` (`!evt.totalShifts`) không phân biệt được "đã logout" với "server chết". `getEventWorkers` trả `[]` cho mọi lỗi. **Fix:** rethrow 401/5xx, chỉ trả `null` khi thật sự rỗng.

### 3.6 [Web] Xoá event ở local có thể lệch với server
- **File:** `web/src/features/events/hooks/useEvents.js:116-145` — ghi `eventId` vào `localStorage['cani_deleted_events']` để ẩn ngay, rồi gọi backend soft-delete ở try/catch **riêng** chỉ `console.warn` → UI ẩn event **kể cả khi backend xoá thất bại**. `loadEvents` còn merge `DEMO_EVENTS` khi API rỗng. Fix: rollback bản ẩn local nếu backend lỗi; một nguồn sự thật duy nhất.

### 3.7 [Mobile] IP LAN cứng trong interceptor toàn cục
- **File:** `mobile/lib/core/network/dio_client.dart:32-56` — khi lỗi tới `localhost`, retry sang IP `192.168.100.31` hardcode. IP đó là máy của một dev, còn `catch (_) {}` rỗng nuốt exception gốc → user chỉ thấy "no response".
- **Fix:** đưa vào `ApiConstants` để override được, hoặc xoá hẳn.

### 3.8 [Mobile] 401 handler vứa token vĩnh viễn khi lỗi mạng thoáng qua
- **File:** `mobile/lib/core/network/auth_interceptor.dart:83-106` — trong block refresh, **mọi exception** đều làm `inMemoryToken = null` → một blip mạng là mất phiên. Đồng thời tạo 2 `Dio()` mới mỗi lần 401, không đóng, không có interceptor.
- **Fix:** chỉ clear token khi lỗi **xác thực** (401/403 từ refresh endpoint), không clear khi lỗi mạng.

### 3.9 [Mobile] State management thiếu nhất quán + file 1.646 dòng
- `shift_detail_execution_screen.dart` (1.646 dòng) gộp countdown timer, GPS, checklist CRUD, upload progress, state machine hành động trong một `ConsumerState`.
- `my_assignments_screen.dart` (656 dòng) giữ list proposals **cục bộ** thay vì qua provider → số đếm ở Home (`proposalsCountProvider`) và list ở tab có thể **mâu thuẫn**.
- Fix: đưa list sang provider; tách file >1.000 dòng thành ≤3 sub-widget.

## 7. Lưu ý cho hội đồng bảo vệ

- **H2 profile là auth bypass hoàn toàn** (`JwtConfig.h2JwtDecoder`: mọi token đều được chấp nhận, fallback về `worker@cani.vn`). Profile này **không được** chạy trên máy dùng chung / host demo công khai — cần nêu rõ trong tài liệu bàn giao.
- Token lưu ở `localStorage` (web) là lựa chọn chuẩn cho stack này; chuyển sang httpOnly cookie cần đổi backend, không phải lỗi mã.
- Supabase anon key trong `.env` là an toàn theo thiết kế; **không có secret nào lọt vào git history** (đã verify `git log --all` + `git check-ignore`).
